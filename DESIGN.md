# Design System: VS Gammon

## Overview

**Creative North Star: "The Analysis Desk"**

A navy desk at night with one lit object on it: the blue backgammon board. Everything else on the screen is the paperwork beside it, numbers, move lists, severity chips, quietly laid out in slate panels that step up a few percent in lightness per level. The world is deliberately the category standard for backgammon and chess analysis (BackgammonGalaxy's blunder review, Lichess analysis, Linear's product shell, Duolingo-style right/wrong feedback) done at full craft, not a novel aesthetic. Recognition is the feature: a strong player should know where to look before reading a word.

Density is that of a product tool used for long evening sessions with keyboard and mouse: 14px body, 36px controls, 16px grid gaps, panels with hairline rings instead of shadows. Dark (navy ink) and light (cool paper) are both first-class and share every token name; only values change. Colour carries meaning in exactly three families (one blue for action, a yellow/orange/red severity ladder plus green for correct, and the four arrow colours on the board), and every coloured meaning is also carried by a label, a dot or a shape.

The shell refuses the generic Material-card look and the "grey screen with one blue button": surfaces are tonal, not white boxes floating on drop shadows, and the board, not a hero card, is the visual centre of every page that has one.

**Key Characteristics:**
- Navy ink canvas (dark) or cool paper (light), slate panels with a 1px ring, one blue accent.
- A Galaxy-style two-tone blue board with white and indigo checkers as the main object.
- Severity ladder: doubtful yellow, bad orange, very bad red, good green; always labelled.
- Move arrows: red = game move, green = best, amber = yours, white = any candidate.
- Inter throughout, tabular figures on every number, tight negative tracking on large type.
- Keyboard-first: keycaps shown inline in buttons, `\` collapses the sidebar rail.

## Colors

A cool navy-and-slate neutral field with one saturated blue for action and a small, strictly semantic set of warm signal colours.

### Primary
- **Galaxy Action Blue** (`accent`): the only action colour. Primary buttons, the active nav fill (as `accent-soft`), focus rings, the PR trend line and its area fill, the due-count badge, selected rows. `accent-text` is the readable blue for links and active nav labels on dark; `accent-hover` darkens on hover.

### Secondary
- **Board Felt Blue** (`board-felt`, `point-a`, `point-b`): the two-tone board. A separate blue family from the accent, lighter and softer, so the board reads as an object, not a control. The board stays blue and dark-framed in both themes (`board-frame`, `tray`).
- **Ivory and Indigo Checkers** (`checker-1`, `checker-2` with their `-edge` and `-text`): player 1 white, player 2 indigo. Also used for the player swatches beside the board and as the two halves of the win-probability bar.

### Tertiary
- **Severity Ladder** (`doubtful` yellow, `bad` orange, `vbad` red, each with a `-soft` tint): error classification in chips, counts, phase bars, list text and history icons. `good` green marks correct answers, best moves and wins. `good-strong` and `vbad-strong` are the solid fills behind white text (Continue after a right/wrong answer, the feedback mark, the progress bar).
- **Arrow Code** (`arrow-game` coral red, `arrow-best` green, `arrow-yours` amber, `arrow-candidate` white): move arrows on the board, mirrored in the move-pill dots, the answer-line strokes and the `best` / `game` / `you` tags.

### Neutral
- **Navy Ink** (`canvas`): page and sidebar background. Light: `canvas-light`, a cool paper grey.
- **Slate Panel** (`surface`) → **Raised** (`surface-raised`) → **Hover** (`surface-hover`) → **Overlay** (`surface-overlay`): each level a few percent lighter in dark mode; in light mode all resolve to white and depth comes from the ring.
- **Well** (`inset`): recessed fields, segmented-control tracks, chips, progress tracks, the XGID strip, move pills. Darker than the canvas in dark mode.
- **Hairlines** (`line`, `line-strong`): translucent slate rules for dividers, table rows, panel rings; `line-strong` for control borders and hover.
- **Text ramp** (`text`, `text-2`, `text-3`, `text-4`): primary, secondary, captions and labels, disabled/rank numbers.

### Named Rules
**The One Blue Rule.** `accent` is the only colour that means "do this". Never use a severity or arrow colour for a neutral action, and never introduce a second action hue. The only exceptions are the Duolingo-style Continue buttons after an answer (`good-strong` / `vbad-strong`), which echo the verdict.

**The Arrow Code Rule.** The four arrow colours mean the same thing wherever they appear: board arrow, pill dot, answer-line stroke, tag. A new surface that shows a move uses this code or no colour at all.

**The Labelled Signal Rule.** Severity and correctness are never colour alone: a chip carries its word ("Very bad") plus a square dot, a count sits in its column, a feedback bar carries an icon and a headline. Colour reinforces; text decides.

## Typography

**Display Font:** Inter (self-hosted variable woff2, weights 100–900), falling back to -apple-system, BlinkMacSystemFont, Segoe UI, system-ui
**Body Font:** Inter
**Label/Mono Font:** Inter for labels; ui-monospace / SF Mono / Menlo only for the XGID string

**Character:** One neutral grotesque used the way Linear and BackgammonGalaxy use theirs: invisible at body size, crisp and tightly tracked at stat size. Inter is a deliberate choice, not a default: it matches the category's product-UI idiom, its tabular figures align equities and pip counts, and its variable weights allow the in-between 550 and 650 the system relies on. Character variants `cv11` and `ss03` are on globally.

### Hierarchy
- **Display** (750, 64px, 1): the session score on the practice summary only.
- **Stat** (650, 30px, 1.15, tabular): the dashboard stat strip values; 22px and 20px variants for deck and mini stats.
- **Headline** (650, 26px, 1.2): page `h1`, one per page; 22px below 640px.
- **Prompt** (650, 24px, 1.25): the practice question ("chessgamm0n to play").
- **Title Large** (650, 18px): position title in review, featured mistake, feedback headline (700).
- **Title** (600, 15px): panel headings, empty-state headings; 16px for dialog and settings section titles.
- **Body** (400, 14px, 1.5): default UI text, table cells, move notation (600 when it is the subject).
- **Body Small** (400, 13px): secondary rows, candidate tables, hints, buttons in `sm`.
- **Label** (550, 12px, sentence case): field labels, stat labels, table headers, captions, chips. Never uppercase, never tracked out.

### Named Rules
**The Tabular Numbers Rule.** Every number that can sit above or beside another number (equities, PR, pips, scores, counts, percentages, timestamps) uses tabular figures. Equities are signed with a true minus (−) and three decimals.

**The Tight Large Type Rule.** Tracking tightens as size grows: 0 at 14px and below, −0.01em at 15–16px, −0.015 to −0.02em at 18–24px, −0.022 to −0.025em at 26–30px, −0.04em at 64px.

**The Sentence-Case Label Rule.** Labels are 12px / 550 / `text-3` in sentence case. Hierarchy comes from weight and colour, not capitals or letter-spacing.

## Layout

A fixed app shell: a 232px sidebar (collapsible to a 68px icon rail with `\`, remembered per browser; review and practice default to the rail) and a main column padded 28px top, 36px sides. Pages open with a page head: `h1` plus a 14px `text-3` subline on the left, actions on the right, bottom-aligned, 24px below.

- **Dashboard:** a 12-column grid with 16px gaps; a full-width four-cell stat strip, then 7/5 splits (trend or featured mistake beside equity-by-phase; mistakes list beside a stacked practice deck and recent matches).
- **Review:** three columns, decision list 300px / board (flexible) / analysis 292px. The list is sticky and as tall as the viewport.
- **Practice:** stage (flexible) beside a 340px side column, with a session bar (filter chips, progress, count) above.
- **Settings:** a 180px sticky in-page nav beside a content column capped at 760px; descriptions capped at 64ch.

Panel internals use 20px vertical and 22px horizontal padding; list rows 12px × 20px; table cells 12px × 14px. Inside panels, sections divide with hairlines, not gaps.

Responsive: at 1280px the review analysis column drops under the board, 7/5 splits stack, practice goes single-column, settings nav hides. At 980px the sidebar is forced to the rail, main padding drops to 20px × 18px, review stacks fully, the stat strip goes 2 × 2. At 640px the sidebar becomes a 60px bottom tab bar (44px targets), main padding 16px × 14px with 84px bottom clearance, featured layouts stack.

### Named Rules
**The Board First Rule.** On any page with a board, the board takes the flexible column and is sized from the viewport height (`max(360px, (100vh − 270px) × 1.27)` in review, `max(380px, (100vh − 410px) × 1.27)` in practice) so the whole position is visible without scrolling. Side columns are fixed widths; the board never shrinks to make room for numbers.

## Elevation & Depth

Flat and tonal. Resting surfaces get no drop shadow: a panel is a slightly lighter slate (or white in light mode) with a 1px `line` ring (`shadow-1`), and depth between levels comes from the `canvas` → `surface` → `surface-raised` → `surface-overlay` steps and from recessed `inset` wells. Real shadows appear only on things that float above the page: the toast and the modal dialog (`shadow-3`), plus a hairline lift on the active segmented option.

### Shadow Vocabulary
- **Ring** (`box-shadow: 0 0 0 1px var(--line)`; light adds `0 1px 2px rgba(15, 23, 42, 0.04)`): every panel at rest.
- **Floating** (`box-shadow: 0 0 0 1px var(--line-strong), 0 24px 64px rgba(2, 6, 23, 0.55)`; light `0 0 0 1px var(--line), 0 20px 48px rgba(15, 23, 42, 0.18)`): toast and dialog only.
- **Inset border** (`box-shadow: inset 0 0 0 1px var(--line-strong)`): secondary and danger buttons, segmented tracks (`line`), move pills; a 1.5px inset ring in the pill or `good` colour marks a selected move pill or the best cube action.
- **Focus** (`outline: 2px solid var(--accent); outline-offset: 2px` on `:focus-visible`; fields use `border-color: var(--accent); box-shadow: 0 0 0 3px var(--accent-soft)`).

### Named Rules
**The Ring Not Shadow Rule.** Borders are drawn as 1px shadows or inset rings, never as drop shadows on resting content. A blurred shadow means "this floats above the page" and is reserved for toasts and dialogs.

## Shapes

Gently rounded, never pill-shaped except for status dots and the count badge. A five-step radius scale: `xs` (4px) for keycaps, tags, result labels and the focus outline; `s` (6px) for buttons, fields, nav items, severity chips; `m` (10px) for large buttons, segmented tracks, move pills, cube rows, toasts; `l` (14px) for panels, the dropzone and the board frame; `xl` (18px) for dialogs. Status dots and swatches are circles; severity dots are 6px squares with 2px corners, so severity is shape-distinct from status. The board itself is drawn in SVG: a 14px-radius frame, triangular points, ringed checkers with an inner ring at 62% radius, rounded dice and cube in ivory with navy pips.

## Components

### Buttons
Compact, quiet, one obvious primary.
- **Shape:** gently rounded (6px); large buttons 10px.
- **Primary:** `accent` fill, white 14px / 550 text, 36px tall, 14px side padding, 8px icon gap. `lg` is 44px / 15px for the page's one main call to action ("Practise 9 due", "Check"); `sm` is 30px / 13px for in-panel actions.
- **Hover / Focus / Active:** hover moves to `accent-hover` (120ms); press scales to 0.97 (100ms); disabled drops to 45% opacity; focus shows the 2px accent outline.
- **Secondary:** `surface-raised` fill with an inset `line-strong` ring, `text` label; hover to `surface-hover`.
- **Ghost:** transparent, `text-2`; hover fills `surface-hover`. Used for icon-only tools (36px or 30px square).
- **Danger:** transparent with ring, `vbad` text; hover tints `vbad-soft`.
- **Go / Stop:** after a practice answer, Continue turns `good-strong` (right) or `vbad-strong` (wrong).
- **Keycaps:** a 20px keycap rides inside the button for its shortcut (Undo ⌫, Check ↵); on filled buttons it is a translucent white chip, on secondary/ghost an `inset` well with a 1px bottom edge.

### Chips
- **Fact chips:** `inset` fill, `text-2` 12px / 500, 24px tall, `strong` parts in `text` / 600. Used for position facts (game, move, score, cube) and session filters.
- **Severity chips:** `-soft` tint with the full colour as text, 22px tall, 12px / 600, preceded by a 6px square dot in `currentColor`. A text-only variant (`sevtxt`, 11px / 650) is used inside dense list rows.
- **Tags:** 18px line, 11px / 650, 4px radius: `best` green, `game` red, `you` yellow, beside candidate moves. Result tags `Won` / `Lost` use the same form.
- **Counts:** 22px rounded squares showing doubtful / bad / very bad counts per player; zero counts fall back to `inset` and `text-4`.

### Cards / Containers
- **Corner Style:** 14px.
- **Background:** `surface`, ringed with `line`.
- **Shadow Strategy:** ring only (see Elevation & Depth).
- **Border:** internal sections split by 1px `line` rules; stat strips and deck rows split vertically by 1px `line`.
- **Internal Padding:** 20px × 22px; panel heads 16px × 20px with a 15px / 600 title on the left and a 12px `text-3` hint or link on the right.
- **Empty states:** centred 28px `text-4` icon, 15px / 600 heading, one sentence capped at 44ch, 48px padding.

### Inputs / Fields
- **Style:** 36px tall, `inset` fill, 1px `line` border, 6px radius, 12px side padding; selects use a custom chevron and 34px right padding. Labels sit 6px above in the Label style.
- **Focus:** border turns `accent` with a 3px `accent-soft` halo; hover moves the border to `line-strong`.
- **Checkboxes / radios:** native, 16px, tinted with `accent-color: var(--accent)`, in a 36px-tall label row.
- **Segmented control:** an `inset` track (10px radius, 3px padding, `line` ring) of 28px options (13px / 550, `text-3`); the pressed option lifts to `surface-raised` with a `line-strong` ring and `text` colour. Used for theme choice and threshold presets. (Flagged once as nested cards by a detector; it is a single control, not a card in a card.)

### Navigation
- **Sidebar:** `canvas` background, 1px `line` right rule, brand mark (a 30px blue rounded square holding an ivory "64" cube) plus name at the top; nav items 36px, 12px icon gap, 14px / 500 `text-2`. Hover fills `surface-hover`; the active page fills `accent-soft` with `accent-text` label and `aria-current="page"`. The Practice item carries the due-count badge (20px, `accent`, 11px / 700 tabular).
- **Foot:** a watched-folder status line with a green dot (soft halo) or grey when off, the light/system/dark segmented control, the collapse toggle, and the engine version in 11px `text-4`.
- **Rail:** collapsed (or under 980px) to 68px: labels hide, the badge moves to the icon's corner, the theme control becomes a single cycling button.
- **Mobile:** under 640px a fixed 60px bottom tab bar on `surface` with 44px icon targets.
- **Icons:** inline Lucide-style SVG, 24px viewBox drawn at 16px, `stroke: currentColor`, stroke-width 1.8, round caps and joins, no fill.

### Board (signature)
The SVG backgammon board (560 × 440 viewBox) is the system's signature object: dark `board-frame` with 14px corners, two `board-felt` halves with alternating `point-a` / `point-b` triangles, a central bar holding the cube, a right-hand `tray` with borne-off checkers drawn as thin slabs, 11.5px / 600 point numbers in `board-label`. Checkers stack to five, then the top one shows the count. Move arrows are 4px round-capped lines in the Arrow Code colours with solid triangular heads. In practice the board is interactive: legal target points fill translucent green with a green outline, selectable checkers get an amber ring (solid when selected). Above and below sit player labels: colour swatch, bold name, score, and pip count right-aligned in tabular `text-3`. Mini boards (no numbers, no dice, no cube) act as thumbnails in mistake lists.

### Move pills and answer lines
Two-up pill buttons under the review board toggle the game and best arrows: `inset` fill, `line` ring, a 9px dot in the arrow colour, tabular move text and a `text-3` cost. Pressed pills lift to `surface-raised` with a 1.5px ring in their own arrow colour. Answer lines repeat the code as a 14 × 3px stroke, label, move and cost in a four-column grid.

### Answer bar (practice feedback)
The bottom strip of the practice stage, separated by a hairline. On an answer the whole bar tints `good-soft` (right) or `vbad-soft` (wrong), a 44px solid circle (`good-strong` / `vbad-strong`) pops in with a check or cross icon, an 18px / 700 verdict headline in `good` / `vbad`, and one plain sentence with the equity lost and the best move. The primary action becomes the matching Go / Stop button with an ↵ keycap. "Shown" answers use `inset` and a `text-4` mark.

### Data rows
Decision rows, mistake rows, match rows and history events share one pattern: a grid row with a 1px `line` bottom rule, `surface-hover` on hover (80ms), `accent-soft` for the current row, a 600-weight subject line and a 12px `text-3` context line ("vs fishsoup · Nov 9 · game 2, move 26"). Middots separate facts.

## Do's and Don'ts

### Do:
- **Do** keep `accent` the only action colour and give each page one `lg` primary button.
- **Do** draw resting panels as `surface` + 1px `line` ring at 14px radius; save `shadow-3` for toasts and dialogs.
- **Do** use tabular figures and a true minus (−) with three decimals for every equity.
- **Do** pair every severity or correctness colour with its word, a dot or an icon.
- **Do** use the Arrow Code (red game, green best, amber yours, white candidate) for any move shown in colour, on or off the board.
- **Do** give the board the flexible column and size it from the viewport height so the full position fits.
- **Do** show keyboard shortcuts as keycaps inside the control they trigger.
- **Do** define every new colour as a token in both the dark and light blocks of `style.css`.
- **Do** use inline 1.8-stroke Lucide-style SVG icons from `ICONS` in `core.js`.

### Don't:
- **Don't** add a second accent hue or use severity colours for neutral actions.
- **Don't** put blurred drop shadows on resting cards, or stack a card inside a card.
- **Don't** set labels in uppercase or with wide letter-spacing, and don't add eyebrow or kicker lines above headings.
- **Don't** use coloured side stripes, gradient text or Unicode glyphs as icons (key symbols such as ⌫ and ↵ belong only inside a keycap).
- **Don't** recolour the board per theme beyond the existing light/dark token pairs; it stays a blue two-tone board in both.
- **Don't** let numbers replace the board: a position is always shown as a board with its numbers beside it.
- **Don't** hardcode hex values in components or JS; reference the `var(--…)` tokens.
